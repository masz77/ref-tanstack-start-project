# Squircle

Standard template UI component that renders containers with Figma-style smooth
corners (squircles) instead of plain CSS `border-radius` arcs. The clip technique
mirrors `squircle-avatar.tsx` from sam-sleeking-portfolio (static SVG `clipPath` in
`objectBoundingBox` units); the curve itself is generated by
[Lisse](https://github.com/JaceThings/Lisse)'s squircle math (MIT, © Jace Attard)
instead of a hand-drawn approximation. No package is installed and no math is
shipped at runtime — the path is precomputed and embedded as a constant.

Source: [squircle.tsx](./squircle.tsx).

## Architecture Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Curve source | Path `d` generated offline by running Lisse's `@lisse/core` squircle math (`generatePath(1, 1, { radius: 0.25, smoothing: 0.6 })`) | Authentic Figma-squircle curvature without installing the package or vendoring ~250 lines of math. |
| Rendering technique | Inline `<svg><clipPath clipPathUnits="objectBoundingBox">` + `clip-path: url(#…)` on a div | Same approach as the portfolio reference component. Normalized 0–1 units scale with the element, so no ResizeObserver/JS measurement is needed. |
| Curvature | Fixed at build time: radius 25% of box, smoothing 0.6 (Lisse default) | Decided 2026-06-10: zero runtime math beats configurable props for a template standard. Re-run the generator and replace the constant if different curvature is ever needed. |
| Component shape | Generic container (`React.ComponentProps<'div'>`), not avatar-specific | Wraps any children; an avatar is just `<Squircle size={96}><img …/></Squircle>`. |
| Scaling | Single `size` prop (number → px, or CSS length) sets square width/height | Decided 2026-06-10: curvature stays fixed; size is the one runtime knob. The normalized clip stretches to any box, so no math runs on resize. |
| What we don't bring in | Lisse's runtime packages, superellipse/clothoid/arc curves, SVG border/shadow effects system, ResizeObserver sync | User decision: "just the squircle." |

> Supersedes the 2026-06-10 initial draft that proposed vendoring the math + ResizeObserver-driven `clip-path: path()`. Replaced same day per user direction to match the portfolio component's static-clipPath approach.

## Data Flow

Static: the component renders a zero-size SVG carrying the `clipPath` definition plus
a div referencing it via `clip-path: url(#squircle-clip)`. The browser scales the
normalized path to the element's bounding box. No state, no effects, no measurement.

## Constraints / Gotchas

- `objectBoundingBox` stretches with the element — the curve is only geometrically
  true on squares. On non-square elements corners distort (accepted trade-off, same
  as the portfolio reference).
- Each instance renders its own `<clipPath>` def with the same id; duplicate ids are
  tolerated by browsers (first match wins) but means the clip definition must never
  become per-instance configurable without switching to unique ids.
- `clip-path` clips the element's own `box-shadow`; put shadows on a wrapper.
- Don't combine with `rounded-*` utilities — `border-radius` intersects the clip and
  cuts the squircle bulge.

## Security Considerations

None — pure presentational component, no inputs cross a trust boundary.
